# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

FlowSync is a course exercise repo, and the course docs (`README.md`, `prompts.md`) are in Spanish. It has two independent npm projects, both TypeScript end to end, with no root workspace:

- `backend/`: AdonisJS 7 API (Lucid ORM on SQLite, VineJS validators, token auth). **Treat it as read-only.** It already exists and the exercise does not change it. Read it to learn the API contract.
- `frontend/`: React 19 + Vite, still the bare Vite template (no router, no API client, no shadcn/ui yet). The work happens here. Use shadcn/ui for UI components. Its components are copied into the repo, not installed as a dependency.

You need Node.js 24 or newer. Older versions fail with `Unknown file extension ".ts"`.

## Commands

Backend (`cd backend`):

```bash
npm install && cp .env.example .env && node ace generate:key && node ace migration:run   # first-time setup
npm run dev          # node ace serve --hmr, http://localhost:3333
npm test             # node ace test (Japa); suites: unit (tests/unit), functional (tests/functional)
node ace test unit                                   # one suite
node ace test --files tests/unit/foo.spec.ts         # one file
node ace test --tests "test title"                   # one test by title
npm run lint && npm run typecheck && npm run format
```

The backend has no tests yet; only `tests/bootstrap.ts` exists. Functional suites start the HTTP server automatically.

Frontend (`cd frontend`):

```bash
npm run dev          # Vite, http://localhost:5173
npm run build        # tsc -b && vite build (this is the type-check)
npm run lint         # oxlint
```

The frontend has no test runner and no formatter configured.

## Backend API contract (what the frontend consumes)

Routes are in `backend/start/routes.ts`, all under `/api/v1`:

| Method | Path | Auth | Body |
|---|---|---|---|
| POST | `/auth/signup` | – | `fullName` (nullable), `email`, `password`, `passwordConfirmation` |
| POST | `/auth/login` | – | `email`, `password` |
| GET | `/account/profile` | Bearer | – |
| POST | `/account/logout` | Bearer | – |

- The validation rules are in `backend/app/validators/user.ts`. Email must be valid, at most 254 chars and unique on signup. Password must be 8–32 chars. `passwordConfirmation` must match `password` and is **required** on signup, even though a product spec may not mention it.
- Every response goes through `ctx.serialize()` (`backend/providers/api_provider.ts`), which wraps the payload in `{ data: ... }`. Signup and login return `{ data: { user, token } }`, and profile returns `{ data: user }`. `user` is shaped by `backend/app/transformers/user_transformer.ts`: `id, fullName, email, createdAt, updatedAt, initials`.
- The default auth guard is `api`, an opaque access token stored in the DB (`config/auth.ts`). Send it as `Authorization: Bearer <token>`. Logout deletes the current token.
- Errors are always JSON (`force_json_response_middleware`). VineJS validation failures return 422 with an `errors` array of `{ field, rule, message }`. Wrong credentials throw from `User.verifyCredentials`.
- In development CORS accepts every origin with credentials, so the frontend calls `http://localhost:3333` directly. Vite has no proxy configured.

## Backend architecture notes

- The request flow is route → controller (`app/controllers`) → validator (`app/validators`) → model (`app/models`) → transformer (`app/transformers`) → `ctx.serialize`.
- Imports use the subpath aliases from `package.json` (`#models/*`, `#validators/*`, `#controllers/*`, …), not relative paths.
- Generated code (do not edit by hand):
  - `database/schema.ts` is regenerated from migrations by `node ace migration:run`. Models extend these generated `*Schema` classes, so columns are not declared in the model.
  - `.adonisjs/` holds the controller index (`#generated/controllers`, used in `routes.ts`) and the Tuyau type registry, both regenerated by the `adonisrc.ts` init hooks when the dev server or ace runs.
- Schema changes always go through a new migration in `database/migrations/`. Never edit an existing migration or the table by hand.
- The SQLite DB file is `backend/tmp/db.sqlite3`.

## Development rules

- **Frontend formatting:** Prettier (default config) formats `frontend/src/**`. A `PostToolUse` hook (`.claude/hooks/format-frontend.sh`, registered in `.claude/settings.json`) runs it on every file an agent edits under `frontend/src`. Do not fight the formatter by hand-formatting code.
- **Before committing frontend changes:** run `npm run build` and `npm run lint` in `frontend/`. Use `npm run format:check` to confirm formatting; `npm run format` rewrites `src` in full.
- **Keep the hook and the scripts in sync:** if you change the formatter or its file list, update both `frontend/package.json` and `.claude/hooks/format-frontend.sh`.
